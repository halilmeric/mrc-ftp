# MRC FTP v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sürüm 1'e izinler, kendi editöründe düzenleme, aktarımı sürdürme, seçilen klasöre indirme ve Hızlı Bakış eklemek.

**Architecture:** Sürüm 1'in yapısı aynen kalır. Mantık ana süreçteki Electron'dan bağımsız modüllere eklenir (`ftp.js`, `transfers.js`, yeni `edits.js`) ve yerel test sunucusuna karşı test edilir; arayüz `window.mrc` köprüsüne eklenen çağrıları kullanır.

**Tech Stack:** Değişmedi. Yeni bağımlılık yok.

**Spec:** `docs/superpowers/specs/2026-11-19-mrc-ftp-v2-design.md` (ve geçerliliğini koruyan `2026-11-19-mrc-ftp-design.md`)

## Global Constraints

- Sürüm 1 planındaki Global Constraints aynen geçerli (güvenlik ayarları, Türkçe metin, şifre kuralları, `.mrcftp-part`).
- Yeni çalışma zamanı bağımlılığı eklenmez.
- Geçici dosyalar yalnızca `app.getPath('temp')/mrc-ftp/` altında durur ve bağlantı kesilince, site değişince, uygulama kapanınca silinir.
- Düzenleme sınırı 10 MB, önizleme sınırı 50 MB.
- Commit mesajları tek satır.

## Review Focus

1. **Sürdürülen aktarım, kaynak değiştiği halde eklenirse** bozuk dosya oluşur: kaynak boyutu ya da tarihi değiştiyse baştan başlamalı. → Task 2 testi.
2. **Geçici dosyası sunucudaki yükleme boyutundan büyükse** (önceki farklı dosyadan kalma): eklemek yerine baştan başlamalı. → Task 2 testi.
3. **Düzenlerken sunucuda değişen dosya** sormadan ezilmemeli. → Task 4 testi.
4. **Editörün "yeni dosya yazıp yerine koyma" kaydı** (dosya kimliği değişir) izlemeyi düşürmemeli. → Task 4 testi.
5. **Geçici klasör yolu, sunucudaki adlardan kurulurken** dışarı taşmamalı (adlar zaten `sanitizeEntries`'ten geçer; uzak yol `..` parçası içeriyorsa reddedilir). → Task 4 testi.

### Task 2: Aktarımı sürdürme

**Files:** Modify `src/main/transfers.js`, `src/renderer/tray.js`; Test `test/transfers.test.js`

**Davranış:** Bağlantı hatasında (iptal ve `AUTH`/`CERT` hariç) geçici dosya silinmez; iş `resumable: true` ve kaynağın `{size, mtimeMs}` (yükleme) ya da `{size, modified}` (indirme) izini taşır. `retry`: kaynak izi aynıysa ve geçici dosya boyutu `0 < n < total` ise `n`'den devam (indirme `downloadTo(part, remote, n)`; yükleme `appendFrom(createReadStream(local, {start: n}), part)`), değilse geçici dosya silinip baştan. İlerleme `n + aktarılan` olarak bildirilir. `clearFinished` yok; hata kartı için `dismiss(id)` eklenir: işi listeden çıkarır ve geçici dosyasını siler. `close()` hata durumundaki işlerin geçici dosyalarını da temizler.

**Interfaces — Produces:** `queue.dismiss(id)`; `window.mrc.transfers.dismiss(id)`; hata kartında "Yeniden dene" yanında "Kapat".

- [ ] Testler (yavaş sunucu): (a) yükleme ortasında `drop()` → `error`, sunucuda `.mrcftp-part` **var**; `retry` → `done`, içerik bayt bayt kaynakla aynı, sunucunun gördüğü ikinci aktarım baştan değil (ikinci denemede bildirilen ilk `bytes` > 0). (b) aynısı indirme için. (c) **Review 1:** hata sonrası kaynak dosya yeniden yazılır → `retry` sonucu yeni içerikle aynı. (d) **Review 2:** geçici dosya `total`'dan büyükken `retry` → doğru içerik. (e) `dismiss` geçici dosyayı siler, iş listeden çıkar. (f) `cancel` hâlâ geçici dosyayı siler. Sürüm 1'in "yarıda kopan üzerine yazma" testi `noParts` yerine "asıl dosya `eski`" + "retry sonrası tam" olarak güncellenir. Run → FAIL.
- [ ] Uygula. Run → PASS.
- [ ] Commit `feat: aktarımı sürdürme`.

### Task 4: Kendi editöründe düzenleme

**Files:** Create `src/main/edits.js`, `test/edits.test.js`; Modify `src/main/transfers.js`, `src/main/ipc.js`, `src/preload.js`, `src/renderer/{app.js,tray.js,index.html}`

**Interfaces — Produces:**
- `createEdits({ dir, getSession, enqueue, open, onChange, interval = 1000 })` →
  - `start(remotePath, entry: {size, modified}): Promise<void>` — `size > 10 MB` → `FtpError('LOCAL', 'Düzenlemek için çok büyük, önce indir.')`; uzak yol `..` parçası içeriyorsa reddeder; dosyayı `dir/<sıra no>/<ad>` altına indirir, `open(localPath)` çağırır, izlemeye alır. Aynı dosya zaten açıksa yeniden indirmez, yalnızca `open` çağırır.
  - `stopAll(): Promise<void>` — izlemeyi durdurur, bekleyen değişiklik varsa önce onu `enqueue` eder, `dir`'i siler.
  - `count(): number`
  - İzleme: `interval` ms'de bir `fs.statSync(localPath)`; `mtimeMs` ya da `size` değiştiyse `enqueue({ direction: 'up', localPath, remotePath, isDir: false, baseline: {size, modified}, note })`.
- `queue.add` yeni alanlar: `baseline` verilirse çakışma kuralı değişir — hedef var ve `{size, modified}` `baseline` ile aynıysa sormadan üzerine yazar; farklıysa `asking` olur ve `job.note = 'Dosya sen düzenlerken sunucuda değişmiş'`. Yükleme bitince kuyruk `onUploaded(remotePath, {size, modified})` geri çağrısını çağırır (yeni `baseline` için; `createQueue({ ..., onUploaded })`).
- `Job.note: string|null` arayüze taşınır; soru kartı varsa onu gösterir.
- `window.mrc.edit.open(remotePath, entry)`, `.stopAll()`, `.onChange(cb: (count) => void)`.

- [ ] Testler: (a) `start` dosyayı indirir, `open` indirilen yolla çağrılır; yerelde dosya değişince bir yükleme işi oluşur ve sunucudaki içerik güncellenir, soru sorulmaz. (b) ikinci kayıt da yüklenir (baseline güncellenmiş). (c) **Review 3:** `start` sonrası sunucudaki dosya dışarıdan değiştirilir, yerel kayıt → iş `asking`, `note` dolu, sunucudaki içerik dışarıdan yazılan; `answer(overwrite)` → yerel içerik. (d) **Review 4:** yerel dosya `rename` ile yerine konarak değiştirilir → yine yüklenir. (e) **Review 5:** `start('/a/../../x', …)` reddedilir. (f) 10 MB üstü reddedilir. (g) `stopAll` klasörü siler, sonra yapılan yerel değişiklik yükleme oluşturmaz. Run → FAIL.
- [ ] Uygula; `ipc.js`'te `open` = `shell.openPath`, `dir` = `temp/mrc-ftp/edit`; `disconnect` ve `before-quit` `stopAll` çağırır. Run → PASS.
- [ ] Arayüz: sunucu menüsünün başına "Düzenle" (yalnızca dosya); durum satırında "N dosya düzenleniyor · Bitir".
- [ ] Çalışan uygulamada doğrula (`open` gerçek editörü açacağından betikte `mrc.edit.open` çağrılır, geçici dosya betikten değiştirilir): yükleme panelde görünür, sunucu içeriği değişir, "Bitir" sayacı sıfırlar.
